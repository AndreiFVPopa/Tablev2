# Quality

One command runs the full gate:

```sh
pnpm quality
```

It chains, in order:

1. `pnpm typecheck` — `tsc -b --noEmit` across the app, node, and e2e project references.
2. `pnpm lint` — ESLint flat config: typescript-eslint strict + stylistic (typed), react, react-hooks, jsx-a11y, sonarjs, import-x, custom boundary rules.
3. `pnpm stylelint` — `stylelint-config-standard-scss` with a camelCase-identifier BEM class-selector pattern for SCSS Modules and a nesting ceiling.

4. `pnpm format:check` — Prettier.
5. `pnpm fallow:arch` — architecture boundaries, forbidden-call rules, circular deps.
6. `pnpm fallow:dead` — dead files, exports, dependencies.
7. `pnpm fallow:health` — complexity + maintainability thresholds.
8. `pnpm test:cov` — Vitest with coverage.
9. `pnpm build` — Vite production build.
10. `pnpm e2e` — Playwright smoke test against the preview server.

`pnpm quality:local` is the pre-push gate: typecheck, lint, stylelint, format:check, Fallow architecture, and Vitest. Playwright and the full build stay in CI.

## Fallow policy

`.fallowrc.jsonc` declares zones for `app`, `table`, `shared`, `students`, `mocks`, `types`, `tests`, and `e2e`, plus the import-rules matrix documented in `ARCHITECTURE.md`. Enforcement:

- `boundary-violation: error`
- `circular-dependencies: error`
- `unused-files / unused-exports / unused-types / unused-dependencies: error`
- `complexity-cyclomatic / cognitive / crap: error`
- `unresolved-imports / unlisted-dependencies: error`
- Advisory React rules at `warn`: `prop-drilling`, `thin-wrapper`, `duplicate-prop-shape`. They surface prop-shape smells but do not block the gate while the demo is this small; promote to `error` when the app grows enough that the signal is reliable.

`boundaries.coverage.requireAllFiles: true` with a small `allowUnmatched` list for root config files means a new source file must land in a zone or the gate fails.

`boundaries.calls.forbidden` bans `fetch` from `table` and `students`. The demo is fixture-only; any host-app networking stays outside those zones.

### Expected empty-zone / ignore warnings

Fallow may print advisory diagnostics that do not fail the gate:

- `tests` zone (`src/**/*.{test,spec}.{ts,tsx}`) — Fallow classifies test files through its own test-entry-point mechanism rather than the boundary matcher, so the zone glob reports zero matches. The zone is retained to document allow-list intent.
- `ignorePatterns` entry for `src/app/routeTree.gen.ts` — the file is gitignored and generated by the TanStack Router Vite plugin; the ignore stays so local/CI generation does not pull it into architecture analysis.

## Enforcement verification

Deliberate violations have been run through the gate and confirmed to fail:

| Violation                                       | Blocker         |
| ----------------------------------------------- | --------------- |
| `src/table/**` importing from `src/features/**` | ESLint + Fallow |
| `fetch()` in `src/features/students/**`         | ESLint + Fallow |
| Dead export in `src/table/**`                   | Fallow          |
| Function over the complexity threshold          | Fallow          |

All four violations were reverted after verification. The baseline passes.

The four rows above cover each enforcement mechanism once:

1. ESLint `no-restricted-imports` + Fallow boundary rule (cross-zone import).
2. ESLint `no-restricted-syntax` + Fallow `boundaries.calls.forbidden` (`fetch` ban).
3. Fallow `unused-exports` (dead code in a portable package).
4. Fallow `complexity-cyclomatic` / `cognitive` / `crap` (health thresholds).

Earlier scratch notes mentioned "six" deliberate checks because two boundary-direction cases were tried before being de-duplicated into row 1, and a sixth candidate (a circular dependency) was skipped because `boundary-violation` already catches the direction. The canonical count is **four**.

## Thresholds

- Coverage (Vitest V8): lines 80, statements 80, branches 75, functions 80.
- Fallow health: cyclomatic 15, cognitive 15, CRAP 30, max function length 80 lines.
- ESLint complexity: cyclomatic 12, cognitive (sonarjs) 15, nested callbacks 4, max function length 120 lines (warn).

Thresholds may only be weakened with a written justification and a reviewer sign-off.

## Suppressions

- Every `eslint-disable` and `fallow-ignore` must carry a `--` reason that states why it exists and under what condition it can be removed.
- `fallow audit` fails PRs that introduce new suppressions without a reason.
- `fallow dead-code` flags stale suppressions that no longer silence a finding.
- Current `src/table` state: `rg "eslint-disable|fallow-ignore|@ts-expect-error|@ts-ignore" src/table` returns **one** match, in `src/table/lib/column-meta.d.ts`: `// eslint-disable-next-line @typescript-eslint/no-unused-vars -- required by the TanStack augmentation shape`. The disable exists because TanStack Table v9's `ColumnMeta<TFeatures, TData, TValue>` interface declares three generics and TypeScript's module-augmentation contract requires the augmentation to repeat the exact same generics, even though our augmentation body only consumes the shared `descriptor` key. It is not a suppression of a real quality finding and can be removed if TanStack simplifies the interface signature.
- Root `eslint.config.ts` retains one deprecation disable for `tseslint.config()` until `eslint/core` `defineConfig` accepts the current react / react-hooks plugin config shapes.

## Definition of done

An implementation is complete only when:

1. The full `pnpm quality` command exits zero.
2. No Fallow finding remains unexplained.
3. No high-risk complexity finding remains.
4. No test is skipped or weakened to hide a failure.
5. No lint rule, Stylelint rule, or Fallow threshold has been weakened without documented approval.
6. No unsafe casts or new suppressions exist without a `-- reason`.
7. Nested schema behavior, URL persistence, and table portability work.
8. The application builds and the browser smoke test passes.
